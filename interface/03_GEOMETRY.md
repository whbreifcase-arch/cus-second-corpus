# Interface · Geometry as Schema

Some validation can be **embodied in the manufactured components** — the shape of the plastic enforces
part of the socket contract, so an illegal build physically will not assemble.

This is the physical face of a Kernel law. The Kernel says: *an exception is a named, owned field,
never a hidden sentence* ([Slice 1 · 01_PRIMITIVES, Law 15](../slice-1/01_PRIMITIVES.md)). Physically:

> **An addition or exception is a named, *visible component* — not something a player must remember.**

## What geometry can enforce
- **Keyed edges per category** — Melee / Ranged / Hybrid / Resource / Reaction / Support packets carry distinct edge profiles; a card whose edge doesn't match a socket **cannot enter it.**
- **Orientation notch** — a card can't be inserted backwards.
- **Slot capacity** — a Frame has a fixed number of slots, so over-capacity builds are physically impossible.
- **Windows** — only a compatible card exposes the correct fields through the Frame's mask.
- **Colour + shape redundancy** — category is communicated twice (poka-yoke), never by hue alone.
- **Explicit sockets for additions** — a Scar, item, Bond, or upgrade occupies a *real slot*, not buried prose. Persistent additions ([Slice 3](../slice-3/01_HARM_LIFECYCLE.md)) take physical space.

## It mirrors the FrameSpec — it doesn't replace it
Keyed geometry is the **material Presentation of the FrameSpec's socket contract**
([01_FRAME.md](01_FRAME.md)). It can *prevent some* illegal constructions at the table, but it is not
the authority: the FrameSpec (digital) is. If shape and schema disagree, the schema wins and the part
is re-cut. Geometry is a **redundant, tangible check**, valued because it teaches and prevents error by
feel — not because it owns the rule.

## The boundary (do not overreach)
Geometry enforces **legality and compatibility** — *does this fit here?* It does **not** infer identity:
a socket never reads packets to deduce Role, Signature, or Archetype ([CON-0023]). Fit is checked;
meaning is authored.
